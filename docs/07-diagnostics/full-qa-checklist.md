# 전체 기능 QA 체크리스트 (Claude API 크레딧 충전 이후)

> 목적: `/api/convert`가 막혀서 검증 못 했던 것들 포함, **전 기능**을 화면 단위로 실제 동작시켜보고 프론트-백엔드 불일치/UI 깨짐/버그를 찾아낸다. 이 문서는 마스터 기획서(`docs/00-master/master-plan.md`)의 확정 기능 백로그·엔드포인트 설계 기준으로 작성됨.

## 원칙
- 한 항목당 "실제로 눌러보고" 결과를 기록한다. 코드만 읽고 "될 것 같음"이라고 넘기지 않는다.
- 실패한 항목은 그 자리에서 고치지 말고 **먼저 전체를 다 훑어서 실패 목록을 만든 다음**, 우선순위 정해서 하나씩 고친다 (자가진단 문서와 동일 원칙).
- 프론트 필드명/타입과 백엔드 응답(DTO) 필드명/타입이 실제로 일치하는지 코드 대조까지 포함한다 — 화면에 값이 비어 보이면 필드명 오타/케이스 불일치일 확률이 높음.

---

## 0. 사전 준비
- [ ] 백엔드 로컬 기동 확인 (`application.yml` profile, DB 연결)
- [ ] `.env` / API 키 값 확인 — Anthropic API 키가 실제로 유효한 크레딧 있는 키인지 (`curl`로 간단한 메시지 호출 1회 찍어서 200 오는지 먼저 확인 — 여기서 막히면 아래 변환 관련 항목 전부 무의미함)
- [ ] `adb reverse tcp:8090 tcp:8090` (Gemma 로컬 서버 쓰면 `tcp:8081`도) — 실기기 baseURL이 `localhost` 기준인지 확인
- [ ] 테스트용 이메일 계정 1개, 카카오/구글 테스트 계정 각 1개 준비

## 1. 인증
- [ ] 이메일 회원가입 `POST /api/auth/signup` — 정상 케이스 + 중복 이메일 에러 케이스
- [ ] 이메일 로그인 `POST /api/auth/login` — 정상 + 비번 틀림 에러 메시지 확인
- [ ] 로그아웃 `POST /api/auth/logout` — 이후 인증 필요 API 호출 시 401 뜨는지
- [ ] 토큰 재발급 `POST /api/auth/refresh` — accessToken 만료 후 자동 재발급되는지 (Flutter interceptor 동작 확인)
- [ ] 카카오 소셜 로그인 `POST /api/auth/social/kakao` — 최초 로그인 시 계정 자동 생성되는지, 두 번째 로그인부터 기존 계정으로 붙는지
- [ ] 구글 소셜 로그인 `POST /api/auth/social/google` — 동일하게 확인
- [ ] 소셜 로그인 응답이 이메일 로그인 응답(`LoginResponse`)과 완전히 같은 구조인지 (Flutter 쪽에서 분기 없이 동일 모델로 파싱되는지)

## 2. 홈 화면
- [ ] `GET /api/news/categories` — 카테고리 칩 목록이 실제 RSS 카테고리와 일치하는지 (프론트가 예전처럼 키워드 매칭으로 되돌아가 있지 않은지 — 마스터 기획서상 이거 버그였음)
- [ ] `GET /api/news?category=` — 칩 선택 시 목록이 실제로 필터링되는지
- [ ] 히어로 카드 + 2단 그리드 레이아웃 — 기사 제목 길 때 잘림/오버플로우 없는지
- [ ] 카드요약 미리보기 "30초 컷" 배지 — 카드요약 스타일 콘텐츠에서만 뜨는지
- [ ] `GET /api/news/popular`, `POST /api/news/{id}/view` — 조회수 기록 후 인기 목록에 반영되는지

## 3. 기사 상세
- [ ] 원문/동화체/소설체/카드요약 세그먼트 전환 — 전환할 때마다 매번 API 재호출하는지 캐시 쓰는지, 로딩 상태 UI 있는지
- [ ] 용어 탭-설명 팝업 — 4개 스타일 전부에서 동작하는지 (마스터 기획서상 "전 스타일 공통")
- [ ] `glossary` 파싱 확인 — 백엔드가 `{{term:용어|뜻풀이}}` 마킹을 정상 파싱해서 순수 텍스트 + 매핑 배열로 분리했는지, 본문에 마킹 문법이 그대로 노출되는 버그 없는지
- [ ] 레벨(LOW/MEDIUM/HIGH) 변경 시 마킹되는 용어 개수가 실제로 차이 나는지
- [ ] 카드요약 화면 — bullet 5개 이하로 제한되는지, "30초 컷" 배지 노출

## 4. 직접 변환 (`/convert`)
- [ ] URL 입력 → 지원 언론사 판별 로직 정상 동작 (지원 안 하는 언론사/유튜브/SNS/페이월 URL 넣었을 때 명확한 에러 메시지)
- [ ] 스타일 3종 선택 카드 — 이번에 갈아끼운 3D 아이콘이 42px 박스 안에서 정상 렌더되는지, 선택 시 파란 테두리 하이라이트 정상 동작하는지
- [ ] "변환 시작하기" 탭 → 실제로 `POST /api/convert` 호출되고 결과 화면까지 정상 도달하는지 (여기가 크레딧 문제로 막혔던 지점 — 이제 실제로 끝까지 되는지 제일 중요하게 확인)
- [ ] 같은 기사+스타일+레벨로 재요청 시 캐시에서 즉시 반환되는지 (`conversion_cache` 테이블 확인 — AI 재호출 없이 응답 오는지 응답 속도로 체감 확인)
- [ ] 변환 실패 시나리오 — Gemma 실패 후 Claude 폴백이 실제로 되는지, 폴백 여부와 무관하게 `verificationPassed`가 항상 true로 박히는 버그가 이번에 고쳐졌는지 재확인 (마스터 기획서에 적힌 알려진 버그)

## 5. 보관함 / 히스토리
- [ ] `GET /api/bookmarks`, `POST /api/bookmarks/{resultId}`, `DELETE /api/bookmarks/{resultId}` — 추가/삭제 후 목록 즉시 반영되는지
- [ ] `GET /api/history`, `DELETE /api/history/{resultId}` — 동일하게 확인
- [ ] 보관함/히스토리 세그먼트 탭 전환 — 각각 다른 데이터 소스인데 화면 상태 꼬이지 않는지

## 6. MY 화면
- [ ] `GET /api/users/me` — 프로필 정보, `lastGlossaryLevel` 값 정상 표시
- [ ] `PATCH /api/users/me` — `widgetEnabled` 토글이 실제로 저장되고 새로고침 후에도 유지되는지
- [ ] 로그아웃 버튼 — 토큰 삭제 + 로그인 화면 이동 확인
- [ ] 설정 메뉴 나머지 항목 (있다면) 하나씩 눌러서 미구현/깨진 화면 없는지

## 7. 위젯
- [ ] `GET /api/widget/today-cards` — 카드요약 3개 정상 반환되는지 (위젯 자체 네이티브 구현은 범위 밖이어도 API 응답은 확인)

## 8. 프론트-백엔드 필드 일치 점검 (코드 대조)
- [ ] Flutter의 각 응답 모델(`*.dart` freezed/json 모델)과 백엔드 DTO 필드명 1:1 대조 — 특히 최근 확장된 필드: `level`, `glossary`, `readingTimeLabel`, `lastGlossaryLevel`, `widgetEnabled`
- [ ] camelCase/snake_case 불일치로 값이 null로 파싱되는 곳 없는지 (Jackson 기본 설정 vs Flutter json_serializable 네이밍 전략 확인)
- [ ] 에러 응답 포맷(`ErrorResponse` 등)이 프론트 인터셉터가 기대하는 구조와 일치하는지 — 에러 메시지가 화면에 안 뜨고 무시되는 케이스 없는지

## 9. UI 무결성 재점검
- [ ] 이번 스타일 아이콘 교체(`style_picker.dart`) 이후 실기기에서 렌더 확인 — 이미지 로딩 지연/깨짐 없는지, 42px 박스 비율 이상 없는지
- [ ] 각 화면 다크모드/시스템 폰트 크기 확대 설정에서 깨지는 곳 없는지 (범위 밖이면 생략 가능, 있으면 기록)
- [ ] 스크롤 영역에서 하단 고정 버튼에 콘텐츠 가려지는 곳 없는지 (특히 변환 화면 하단 CTA, 기사 상세 하단 버튼바)

## 10. 에러/엣지 케이스
- [ ] 네트워크 끊긴 상태에서 각 화면 진입 — 무한 로딩/크래시 없이 에러 상태 UI 뜨는지
- [ ] 토큰 만료 상태로 앱 재시작 — 자동 로그아웃 또는 자동 재발급 중 의도한 대로 동작하는지
- [ ] 빈 데이터 상태 (기사 없음, 보관함 비어있음 등) — 빈 화면 UI 있는지 아니면 깨진 화면 나오는지

## 11. 보고 형식
각 실패 항목마다:
```
### [화면/기능명]
- 재현 방법: 
- 기대 동작: 
- 실제 동작: 
- 원인(코드 레벨까지 확인한 경우): 
- 수정 여부: 완료(커밋 해시) / 원인 파악했으나 미수정(이유) / 원인 불명
```
전부 훑은 뒤 `docs/07-diagnostics/YYYY-MM-DD-full-qa-report.md`로 저장. 이번에도 여러 버그를 한 커밋에 몰아넣지 말고 항목별로 쪼개서 커밋.
