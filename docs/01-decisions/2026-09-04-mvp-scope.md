# 1차 목표 범위: Android APK 시연, 웹 보류

## 무엇을 결정했는가
- 1차 목표는 **Android APK를 스토어 배포 없이 직접 다운로드해서 시연 가능한 상태**로 만드는 것.
- 웹 버전(신규 웹, 구 `apps/아카이브`와는 별개로 논의됐던 것)은 이번 1차 범위에서 제외, 나중으로 미룬다.
- iOS는 이번 1차 목표엔 포함 안 함 — Google/Kakao OAuth 클라이언트는 이미 iOS용도 만들어놨지만, 실제 iOS 빌드/서명/시연은 후순위. Android 우선으로 완성도를 올린다.
- 스토어(Google Play) 등록/서명 배포도 이번 범위 아님 — 디버그 또는 임시 서명된 APK 파일을 직접 공유해서 설치하는 방식으로 시연.

## 왜 그렇게 결정했는가
- 시연이 1차 목적이라 스토어 심사, iOS 인증서/프로비저닝, 웹 별도 빌드 파이프라인까지 지금 다 갖출 필요 없음. 가장 빠르게 "실제로 돌아가는 걸 보여줄 수 있는" 형태에 집중.

## 마스터 기획서 반영
- 2장 아키텍처 방향에 "1차 목표: Android APK 시연" 명시
- 8장 개발 순서에서 Flutter 앱 단계는 Android 빌드/APK 산출 우선, iOS/웹은 이후 단계로 분리
